# 德新物業(立德新)專案工程報價系統

工務處同仁依主管制定的標準單價快速開單，主管審核後提交聯新國際醫院採購。

**建置與部署步驟見 [SETUP.md](./SETUP.md)。**

## 這個系統在解決什麼

| 問題 | 做法 |
|---|---|
| 每個人報價開法不同 | 主管維護唯一一份標準單價目錄，同仁只能選品項填數量 |
| 價格說不出依據 | 每個品項掛佐證來源（官方指數／法規／市場行情／自家歷史成交），列印在報價單上 |
| 原物料波動跟不上 | 品項連動主計總處 CCI 指數與銅價，主管每月更新一次數字即可算出建議價 |
| 工資報價浮動 | 統一為技術工日薪 2,800 元 × 勞基法時段係數（平日 1.0／延時 1.34／休息日 1.67／例假日 2.0） |
| 議價過程沒留紀錄 | 逐項記錄 院方還價 → 我方回應 → 定案價 → 理由，並在低於底價時警示 |

## 角色

- **同仁**：開單、選標準品項填數量、送審、列印。看不到底價，不能改標準單價。
  非標品走「臨時項目」，強制填理由並在報價單上標 ★。
- **主管**：全部同仁功能 ＋ 維護標準單價與底價 ＋ 物價指數 ＋ 議價回應 ＋ 核可退回 ＋ 人員權限。

權限由 Supabase Row Level Security 在資料庫層把關，不是靠前端藏按鈕。

## 架構

```
GitHub Pages（靜態前端）  ──►  Supabase（Auth + Postgres + RLS）
   React + TS + Tailwind          帳號、單價庫、報價單、議價紀錄
```

```
src/
├─ types.ts                 共用型別
├─ lib/
│  ├─ calc.ts               金額公式唯一來源（含送審驗證、指數連動、佐證句）
│  └─ supabase.ts           連線
├─ context/
│  ├─ AuthContext.tsx       登入狀態與角色
│  └─ RefDataContext.tsx    參考資料（分類/品項/指數/佐證/工資係數/系統參數）
├─ components/Layout.tsx    外框與導覽
└─ pages/                   各功能畫面
db/
├─ 01_schema.sql            資料表 + RLS + 觸發器
└─ 02_seed.sql              由 scripts/gen_seed.py 產生的初始資料
scripts/
├─ catalog-v1.json          73 份歷史報價單解析出的品項庫
└─ gen_seed.py              轉換規則（工資日薪制、裝修 m²、佐證掛載）
```

## 資料來源

單價庫由 2025-11 至 2026-08 共 **73 份**立德新對聯新國際醫院的報價單、
**438 筆**工料明細解析收斂而成，共 **201 個標準品項 / 8 分類**。

單價一律以 `複價 ÷ 數量` 回推（PDF 的單價欄會被切碎，複價與數量才可信）。

### 已知的資料限制

- **佐證覆蓋率目前 48%**，105 項待補——主管在「單價維護」勾「只看無佐證」就是待辦清單。
- **裝修類 8 項**歷史以「式」報價、無面積可回推，標記 `needs_area` 待轉 m²。
  新建的 6 個 m² 標準品項取自 2026 台灣裝修市場行情（每坪 ÷3.3058），
  屬住宅行情，醫療場域規格較高，**主管須覆核後調整**。
- 管理費率實測分佈：5% 共 53 件、10% 共 5 件（260818 起的近期案）、9% 共 2 件。
  系統預設 **9%**（使用者指定），可在「物價指數」頁調整。
- 來源報價單本身的錯誤（如 260825 創新教育中心明細加總與小計差 600 元）照原文登錄，未擅自修正。

## 開發

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # 產生 dist/
npm run lint
```

改單價庫的初始資料：改 `scripts/catalog-v1.json` 或 `gen_seed.py` 的轉換規則，
再 `cd scripts && python gen_seed.py` 重產 `db/02_seed.sql`（腳本內有 id 唯一性等自我檢查）。
系統上線後日常調價請直接在系統內做，不要改 seed。
